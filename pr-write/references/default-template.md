# 기본 PR 양식

레포에 `.github/pull_request_template.md`가 **없을 때만** 쓴다. 구조는 개요 / 변경 내용 / 테스트 / 리뷰 포인트로 짧게 잡았다. PR 유형 체크박스와 체크리스트는 두지 않는다(리뷰어에게 정보가 되지 않는다).

## 제목

레포의 커밋 관례를 따른다. 관례가 없으면:

```
type: 한 가지 변경을 한 줄로
```

`type`은 `feat` `fix` `refactor` `style` `docs` `test` `chore`. 70자 안쪽, 마침표 없음.

## 본문

```markdown
## 개요

<무엇을, 왜 바꿨는지 2~3문장. 어떻게는 쓰지 않는다.>

Resolves: #<이슈 번호>   <!-- 없으면 줄 삭제 -->

## 변경 내용

- <영역/파일 단위로 묶은 변경 1>
- <변경 2>

<!-- 모듈 섹션: 감지된 변경 종류의 것만, 이 자리에 넣는다. 해당 없으면 삭제.
     UI 변경 → references/modules/ui.md 의 "## UI 변경"
     서버 변경 → references/modules/server.md 의 "## 서버 변경" (증거 블록) -->

## 테스트

<실제로 실행한 것만 적는다. 예: `npm test` 통과, 로컬에서 /checkout 직접 확인.>
<하지 않았다면 "테스트하지 않음"이라고 쓴다.>

## 리뷰 포인트

<리뷰어가 특히 봐 주었으면 하는 곳, 알려진 한계, 후속 작업. 없으면 섹션 삭제.>
```

## 채우는 규칙

- 비어 있는 선택 섹션(모듈 섹션, `리뷰 포인트`)은 **삭제**한다. 빈 제목만 남기지 않는다.
- `테스트`는 실제로 실행한 것만 적는다. 실행하지 않았으면 "테스트하지 않음"이라고 쓴다.
